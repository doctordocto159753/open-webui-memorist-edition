# WP02 adversarial golden corpus

`memorist-core/tests/fixtures/wp02/golden-corpus-v1.ijson` is the
implementation-independent acceptance corpus for semantic candidate planning.
Its expected semantic units, reference states, evidence spans, dispositions,
and candidate counts are authored data. They are not snapshots of production
output and are not regenerated by the planner.

The companion test oracle reads only the fixture. It does not import the
production planner or proposal-identity implementation. Production results are
passed to the oracle and compared with explicit expectations. Proposal identity
also has fixed UUIDv5 test vectors; it is not tested by comparing two calls to
the same function.

## Coverage

The corpus includes:

- Persian multi-proposition and coordinated-noun messages;
- Persian/English mixed architectural statements;
- transient and durable instructions;
- affirmed, negated, hedged, hypothetical, and questioned units;
- unique and ambiguous same-message references;
- positive and negative assistant-context ratification;
- context-isolation exclusions;
- ZWNJ, Persian/Arabic variants, emoji, combining marks, CRLF, exact typos, and
  fenced code;
- secrets in prose and code plus sensitive personal data;
- WP01 token-boundary and non-authoritative lexical-polarity regressions.

The frozen `SemanticRelation` enum does not contain a free-standing `contrast`
relation. The PostgreSQL/FalkorDB example therefore records two independent
propositions and uses the permitted `elaborates` relation for the explicit
`اما` evidence. It never creates graph authority.

## Mutation obligations

Tests must fail if an implementation:

- drops an expected semantic unit or coverage item;
- guesses a target for an ambiguous reference;
- promotes assistant context to user authority;
- ignores a terminal gate;
- generates random proposal UUIDs;
- admits context across user/session/workspace/project boundaries;
- accepts the historical top-level `items` shape;
- certifies only one member of the ordered memory-extraction bundle.

Lite and Full parity tests consume the same fixture but invoke their actual
storage-backed runtime paths. Comparing the shared pure planner with itself is
not parity evidence.
